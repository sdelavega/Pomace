# Pomace 1.1 — Design

**Status:** Approved in conversation 2026-10-22, pending written-spec review · **Branch:** `release/1.1`
(cut from `codex/administrator-compression`, so ADR-0016 ships in 1.1)

## 1. Purpose

Close the remaining items of [issue #1](https://github.com/sdelavega/Pomace/issues/1)
(installation pain, translations), bring Pomace's distribution up to the standard Tesserae
set (Sparkle updates, Homebrew cask, notarized DMG), and finish the open M4 accessibility
items. Engine work — a validated savings estimator, per-directory compressor measurement
(ADR-0010), compress-on-arrival — is **out of scope** and gets its own 1.2 spec.

### Decided by the user

- Bundle applesauce in the app; keep an Advanced override to a user-chosen applesauce.
- Universal (arm64 + x86_64) build; macOS 14 floor unchanged (ADR-0012).
- Seven machine-translated languages beside English: zh-Hans, es, ja, ko, de, fr, pt-BR.
- Diagnostics are user-initiated only. No telemetry, no automatic upload.
- Sparkle 2 via SwiftPM, keeping ADR-0013 (no `.xcodeproj`), with the release pipeline
  ported from Tesserae.
- An Intel Mac is available for a pre-release runtime check.

### Assumptions (stated in brainstorming, not contradicted)

- Pomace gets its own Sparkle EdDSA key, separate from Tesserae's.
- A notarized DMG replaces the ZIP as the release artifact.
- 1.0.2 has no updater, so 1.0.2 users update manually once; Sparkle starts working from 1.1.

### Success criteria

1. A signed, notarized, stapled universal DMG of 1.1 that passes `spctl` and `stapler validate`.
2. On a user account without Homebrew or the Command Line Tools, Pomace compresses and
   decompresses disposable files using only its bundled compressor.
3. A Sparkle update from a 1.1 release candidate to a later candidate installs from a
   locally served signed feed, and the sweep agent still works afterwards.
4. `brew install --cask sdelavega/tap/pomace` installs the app (checked against the tap
   change locally before publishing).
5. All eight locales are complete in the catalog and their main windows render without
   clipping.
6. The keyboard and VoiceOver checklist in `docs/ACCESSIBILITY.md` passes.
7. `scripts/gate.sh` passes locally and in CI.

## 2. Bundled compressor (ADR-0017, supersedes ADR-0003)

ADR-0003 ("never bundle afsctool") predates Pomace adopting GPL-3.0-or-later (ADR-0008).
applesauce is GPL-3.0, so shipping it inside the app is licence-compatible, provided the
notice and source offer travel with it.

**Build.** `tools/applesauce/` is a separately locked Cargo wrapper crate pinned to an exact
applesauce release, following Tesserae's `tools/applesauce`. `scripts/build-applesauce.sh`
builds `aarch64-apple-darwin` and `x86_64-apple-darwin` with `--locked`, `lipo`s them,
and writes `build/applesauce`. `MACOSX_DEPLOYMENT_TARGET=14.0`. `cargo deny` checks
licences against an allow-list. `build-app.sh` copies it to `Contents/Helpers/applesauce`
and signs it, with hardened runtime and a timestamp on release builds, before signing the app.

**Resolution.** `CompressorTool` resolves exactly one compressor:

| Source | When | Checks |
|---|---|---|
| Bundled | Default | Present at `Bundle.main` `Contents/Helpers/applesauce`, executable, code signature valid, `--verify` supported |
| Custom | User set a path in Settings → Advanced | Absolute path to a regular executable file, `--verify` supported; version shown |

If the custom path fails its check, Pomace uses the bundled copy and shows the reason beside
the setting. It never runs a compressor that failed the capability check. Removing the custom
path returns to the bundled copy. The source and version are shown in the Advanced pane and
included in diagnostics.

**Removed.** Homebrew discovery, PATH search, and the "Install with Homebrew" flow and its
licence-disclosure sheet are deleted along with their tests. The scan-only mode for a missing
compressor stays: if neither source is usable (a damaged bundle, for example), Pomace scans
and explains but does not mutate.

**Elevated runs.** ADR-0016 is unchanged in shape. It elevates the resolved path, and the
confirmation names that exact path. A custom path is labelled "custom" in the confirmation.

**Licence.** The About panel credits applesauce (GPL-3.0) and links its source. The README's
requirements drop the Homebrew prerequisite.

## 3. Universal app

`build-app.sh` builds `PomaceApp` for `arm64` and `x86_64` (`swift build --arch arm64 --arch
x86_64`) in release configuration, and keeps a host-only debug build for development speed.
`scripts/check-bundle.sh` asserts:
- both architectures in the app binary, the helper, and Sparkle
- valid signatures, inside-out
- `Info.plist` keys present (`SUFeedURL`, `SUPublicEDKey`, `SURequireSignedFeed`)
- no debug or test hooks in a release bundle

## 4. Updates (Sparkle 2)

- **Dependency.** Sparkle is a SwiftPM binary dependency pinned to an exact version, depended
  on only by `PomaceApp`. `build-app.sh` embeds `Sparkle.framework`, including its
  `Autoupdate` helper, `Updater.app` and XPC services, in `Contents/Frameworks`, and adds the
  `@executable_path/../Frameworks` rpath. Signing is inside-out: Sparkle's nested helpers,
  then the framework, then `Contents/Helpers/applesauce`, then the app. `--deep` is never used.
- **Info.plist.** `SUFeedURL` = `https://sdelavega.github.io/Pomace/appcast.xml`, plus
  `SUPublicEDKey`, `SURequireSignedFeed` = true, `SUEnableAutomaticChecks` = true,
  `SUScheduledCheckInterval` = 86400 and `SUEnableSystemProfiling` = false.
- **Keys.** Claude runs Sparkle's pinned `generate_keys` with a Pomace-specific keychain
  account, after the user approves. The private key stays in the user's login keychain, and
  only the public key enters the repository.
- **UI.** An app-menu "Check for Updates…" item, and a "Check for updates automatically"
  toggle in Settings → General.
- **Headless mode.** `--sweep-all` never creates the updater. Before Sparkle installs an
  update, the app asks the sweep coordinator whether a run is active. If one is, the install
  waits until it ends. A batch is never interrupted. After relaunch, the agent's
  `SMAppService` registration is re-validated and reported honestly, as it is today.

## 5. Release pipeline

`release/release.sh <version>` is ported from Tesserae's `scripts/release.sh` and adapted to
the scripted SwiftPM build:
1. Run the gate on a clean tree.
2. Build the universal app with Developer ID signing and a secure timestamp.
3. Make a DMG, sign it, notarize it with the existing `Pomace Notary` keychain profile,
   staple it, and validate it. Assess both the DMG and the mounted app with `spctl`.
4. Generate the appcast with pinned Sparkle tools, whose SHA-256s are checked in. Generation
   uses a fresh directory holding only this run's DMG, its notes, and the published appcast
   fetched from `origin/gh-pages`.
5. Write `dist/MANIFEST`: version, commit, DMG SHA-256.

`release/publish.sh <version>` is a separate step that the user triggers. It re-verifies
`MANIFEST` against HEAD and the DMG bytes, creates the tag and GitHub release, pushes the
appcast to `gh-pages`, and updates `Casks/pomace.rb` in `sdelavega/homebrew-tap` from
`packaging/pomace.rb.template` (`auto_updates true`, `depends_on macos: :sonoma`, zap
stanzas for Pomace's Application Support, Preferences, Caches, Saved State, and the
LaunchAgent registration). It never runs without the user's explicit go-ahead.
`release/README.md` documents both steps. Release notes for 1.1 tell 1.0.2 users that this
is their last manual update.

## 6. Localization

Today 3 strings go through the catalog. The rest are hard-coded, and a bare `Text("…")` in a
SwiftPM target looks in the main bundle, not `.module`.

- **Core returns data, not prose.** PomaceCore's user-facing English is replaced by typed
  values that carry the data the text needs: exclusion reasons, policy justifications, run
  outcomes, deferral reasons, errors. An enum such as `ExclusionReason.hardLinked(linkCount:)`
  is one example. The app maps each case to a catalog string. Log messages stay English.
- **App strings.** Every user-visible string goes through `AppStrings` or `Text(_:bundle:
  .module)` with a stable key and a translator comment. Plurals use catalog plural variants.
  Bytes, counts, durations and dates use locale-aware formatters.
- **Languages.** en (source), zh-Hans, es, ja, ko, de, fr, pt-BR. Translations are
  machine-made, reviewed by a second model, and marked "machine-translated — corrections
  welcome" in the About panel and README. `docs/TRANSLATING.md` explains how to submit a
  correction.
- **Checks** (in the gate):
  - every key has a value in all 8 locales, and none is marked stale or needs-review
  - format specifiers and plural categories match the source
  - no hard-coded user-facing `Text("literal")` remains (a lint)
  - a pseudo-locale build (`-AppleLanguages`, accented and lengthened) is used for a manual clipping pass
  - screenshots of each locale's main windows are reviewed before release

## 7. Accessibility

- **Keyboard.** Logical focus order. Sidebar, table, inspector and dialogs are reachable
  and operable without a mouse. Menu commands with shortcuts for Scan, Rescan, Compress,
  Decompress and Stop. Default and cancel buttons are correct in every confirmation.
- **VoiceOver.** Labels, values and hints on custom views: the coverage bar (spoken as
  percentages and sizes), the history timeline (as a list of dated values), state badges,
  progress, and exclusion reasons.
- **Display settings.** Respect the system text size without clipping. Reduce Motion
  disables decorative animation. Increase Contrast and Differentiate Without Color: state is
  never conveyed by colour alone.
- **Verification.** Automated: an AX-tree check script asserts every interactive element has a
  label, plus `performAccessibilityAudit` if a UI-test harness proves workable with the
  scripted bundle. Manual: `docs/ACCESSIBILITY.md` holds a VoiceOver and keyboard walkthrough
  checklist, completed before release.

## 8. Report a Problem

Help → Report a Problem builds a plain-text report:
- app version and build, macOS version, architecture
- compressor source and version
- whether the agent is registered
- the last 500 Pomace OSLog entries (via `OSLogStore`, current process scope plus the agent's
  persisted run history from the store)
- Pomace's own `.ips` crash reports from the last 30 days in `~/Library/Logs/DiagnosticReports`

**Redaction.**
- The home directory becomes `~`.
- Path components below a watched or scanned root become `<folder-N>`, keeping only the
  root kind (Applications, Homebrew, user folder, external volume).
- Volume names are replaced.
- Usernames and host names are removed.

The user sees the full report in a sheet before anything leaves the app. They can Copy, Save
As…, or Open GitHub Issue, which opens a pre-filled `issues/new` URL with the body truncated
to fit and a note to attach the saved file if it was truncated. Nothing is sent
automatically. Redaction has unit tests over representative inputs.

## 9. Gate

`scripts/gate.sh`, run by CI and before every task review:
- `swift test`
- the bundled applesauce build and `cargo test`/`cargo deny` for `tools/applesauce`
- `Tests/integration/sparse-image.sh`, extended to round-trip through the bundled helper
- universal `build-app.sh release` (ad-hoc signed when no identity)
- `scripts/check-bundle.sh`
- the localization checks

CI (`.github/workflows`) runs the same script on macOS.

**Manual pre-release checks:**
- Clean-account compress and decompress on disposable files.
- The local Sparkle update test.
- VoiceOver and keyboard walkthrough.
- Locale screenshot review.
- On the Intel Mac: launch, scan, compress and decompress a disposable folder, and
  update-check.

## 10. Phases

1. Bundled compressor and ADR-0017 (§2).
2. Universal app and bundle check (§3).
3. Sparkle integration (§4).
4. Release pipeline, dry-run only (§5).
5. Core typed reasons and app catalog migration (§6, first half).
6. Translations and localization checks (§6, second half).
7. Accessibility pass (§7).
8. Report a Problem (§8).
9. Docs: roadmap truth-up (M5 signing and notarization done, 1.2 entry for engine work),
   README, SAFETY, ARCHITECTURE.

## 11. Non-goals

- Engine changes: estimator, compressor measurement, FSEvents. These are for 1.2.
- Archive mode, per-file-type policies, CLI or Shortcuts.
- Automatic crash upload or analytics.
- Human translations, and languages beyond the eight.
- Lowering the macOS floor.

## 12. Risks

- **Sparkle without Xcode.** Embedding and signing its nested bundles by script is the
  likeliest failure. `check-bundle.sh` and the local update test exist to catch it.
- **Strings refactor breadth.** It touches most UI files and Core's public types. Typed
  reasons must keep their existing tests meaningful.
- **Translation layout.** German and Portuguese run long, and CJK fonts change line heights.
  The pseudo-locale and screenshot passes catch this.
- **Elevated compressor path.** A custom compressor under ADR-0016 runs as root. The
  confirmation must make that unmistakable, and the high-effort final review covers it.
